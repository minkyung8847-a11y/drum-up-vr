# VR 공통 판정선과 고정 음악 플레이어

2026-11-08. 악기 모델/배치, 스틱/Grip/USB 페달 입력, 사운드/진동, 음원/JSON, 저장된 싱크값과 카운트다운은 변경하지 않았다.

## 위치와 노트 경로

`vrNoteHighway.ts`의 `VR_JUDGMENT_LINE`에서 선의 두께/여백/높이/깊이와 레인의 먼 쪽 높이를 조절한다. 초기 드럼 hit surface의 월드 좌표와 반지름으로 키트 범위를 구한다. 모든 악기의 도착점은 같은 Y와 Z를 사용하며 X만 다르다. 하나의 `vr-judgment-line` 메시가 전체 키트를 가로지른다. 중앙 코어와 낮은 알파의 화이트 헤일로 및 양 끝 페이드를 한 셰이더 안에서 그린다. 배경판은 없다.

레인은 악기별 ID를 유지한다. 진행률 0이 판정선 교차점이고 1이 먼 시작점이다. 모든 노트가 `positionAt(remaining / travel)`을 사용하므로 서로 다른 레인에서도 remaining=0일 때 중심이 공통 선과 정확히 만난다. 키트가 생성된 뒤의 고정 좌표를 쓰며 고개 이동에 따라 바뀌지 않는다. 노트 레인의 시작 높이는 기존 통합 패널을 가리지 않도록 검증했다.

## 보존한 시간식

- 도착 시각(ms) = 기존 전달된 note.time × 1000 + 기존 noteSyncMs
- 현재 악보 시각(ms) = (기존 audio.currentTime − 기존 media.offset) × 1000
- remaining = 도착 시각 − 현재 악보 시각
- 사랑으로 전달 note.time은 기존 JSON 시간 + 기존 chartOffsetSeconds 그대로다.
- 사랑으로 media.offset은 기존 LOVE_COUNT_IN = 4 × 60 / 62다.
- 기존 기본 곡 오프셋 2.90초, 사용자 저장 곡 오프셋, 보정값, MP3 예약 시작의 0.035초, 출력 지연 보정은 그대로다.
- MUSIC 이동 시간 NOTE_TRAVEL_TIME=2.0초, 기존 데모 이동 시간 3.0초를 유지한다.

`vrMusicSong.ts`, `vrNoteSync.ts`, `songPracticeTiming.ts`, MP3/JSON을 수정하지 않았다. 새로운 높이를 맞추기 위해 타이밍 수치를 보정하지 않는다.

## 성공/MISS와 일시정지

기존 악기 ID 및 Perfect/Great 허용 범위로 판단하며 resolved 플래그를 한 번만 설정한다. 성공한 원본 노트는 즉시 활성 레인과 장면에서 제거한다. 별도의 고정 풀(16개)에서 흰 노트 잔상/확산 링/선의 국소 플래시/판정 텍스트를 200ms 동안 표시한다. 잔상은 낙하하지 않고 타격 당시 중심에 고정되어 축소·페이드한다. MISS는 더 약한 잔상/텍스트로 짧게 페이드한다. 성공과 MISS 모두 기존 정확도/집계식을 유지한다.

효과의 나이도 악보/오디오 시계로 계산한다. PAUSE에서는 노트 위치·효과·타격 판정·자동 MISS를 갱신하지 않는다. PLAY는 기존 transport의 동일 위치에서 재개한다. 물리 드럼의 사운드/애니메이션은 연주 입력 경로를 그대로 유지한다.

## 음악 플레이어

`vrMusicPlayer.ts`의 `VR_MUSIC_PLAYER`에 크기/위치를 둔다. 플레이어는 scene의 직접 자식이며 카메라, XR rig, 이동 가능한 통합 패널의 자식이 아니다. 키트에서 만든 판정선의 중앙 X, 선보다 0.48m 높은 Y, 선보다 0.12m 앞인 Z에 한 번 배치한다.

앨범 커버, 곡명/아티스트, 재생·일시정지, 경과/전체 시간과 진행 바를 표시한다. 플레이어 시간은 `transport.currentTime − transport.preroll`이며 전체 길이는 실제 디코딩된 MP3 buffer.duration이다. chartOffset/noteSync를 진행률에 넣지 않는다. 기존 카운트다운 중에는 숨기고 종료 뒤 표시하며 곡 종료/이탈 시 숨긴다. 캔버스는 최대 10Hz로 갱신하고 정지 상태에서는 다시 그리지 않는다.

재생 버튼은 기존 통합 패널의 컨트롤러 레이/Trigger 이벤트 경로에 연결했다. 해당 버튼을 가리키는 손의 드럼 충돌은 기존 패널과 동일하게 잠깐 제외한다. VR/AR 전환과 패널 이동은 기존 경로를 사용한다.

## 2026-11-08 추가 개선: 중심 정렬/노트 채움/효과/패널 조절

- 판정선은 높은 심벌(크래시·라이드) 중 낮은 쪽보다 6cm 낮게, 탐 상단보다는 최소 3.5cm 높게 배치한다. 현재 키트 기준 Y=0.96m다. 동일 Y/Z의 하나의 선을 유지한다.
- 등간격 슬롯 배치를 제거했다. 초기 연주 시점에서 실제 hit surface 중심을 선의 Z 평면에 투영한다. 킥의 실제 X=0이 정확한 중앙 레인이다. 다른 악기도 동일한 투영식을 써 정면에서 악기 중심과 맞춘다. 고개가 움직여도 좌표를 다시 배치하지 않는다. 원근상 정렬은 초기 기준 시점에 대한 정렬이다.
- 노트는 셰이더로 바깥 링을 유지하며 내부가 아래부터 채워진다. fill=clamp(1-remaining/travel,0,1). 도착 때 fill=1이며 기존 시각 식은 그대로다. 노트마다 독립 uniform과 재사용 재질을 써 여러 노트의 채움이 섞이지 않고 캔버스를 매 프레임 만들지 않는다.
- `vrDrumFeedback.ts`는 노트 엔진과 독립적인 8개 컬러 테두리/타격 파동을 제공한다. 숨겨진 충돌 프록시 대신 보이는 헤드/심벌에 붙인다. 평소 opacity=.52, 타격 순간 밝아지고 240ms 파동이 퍼진다. head 색 반응도 복구하고 원래 색으로 돌아온다. 기존 드럼 메시/배치/충돌 좌표는 유지한다.
- 플레이어는 반투명 차콜 네모 패널, 커버/곡명/아티스트, 실제 MP3 진행 바, 이전/재생·정지/다음만 표시한다. 별/잠금 등 추가 아이콘은 넣지 않는다. 사용자 선택에 따라 이전/다음은 ±10초다.
- ±10초 이동은 기존 transport.pause/currentTime/play를 사용한다. 카운트다운/곡 오프셋/보정값을 바꾸지 않는다. 기존 seeked 정책처럼 이동 구간의 연습 집계는 재시작하며 이미 지난 노트를 한꺼번에 MISS 처리하지 않는다. 정지 중 이동하면 새 위치의 노트를 한 번 배치하고 다시 정지한다.
- `vrWorldPanel.ts`는 월드 패널에 공통으로 적용할 수 있는 조절 모듈이다. **하단 핸들을 Trigger로 누른 채** 컨트롤러 이동=패널 이동, thumbstick 위/아래=확대/축소, 좌/우=가까이/멀리다. 잡지 않은 상태에서 크기·거리는 바뀌지 않는다. 크기 .55~1.75배, 거리 .70~4.5m, deadzone=.3을 적용한다. dpad도 같은 방향에 대응한다.
- 놓으면 위치/방향/크기를 localStorage에 저장한다. 기존 통합 패널 pose 키/버전은 호환하며 scale이 없는 이전 값은 1배다. 플레이어 키는 drumup.vr.music-player-pose.v1이다. 드래그 중 다른 버튼/다른 손 입력이 재생 조작으로 이어지지 않는다.
- 컨트롤러 포인터는 손별로 고정된 두 레이를 사용한다. 추가 키보드/화면 XR 소스는 포인터 슬롯에 참여하지 않으며 profiles가 없어도 안전하게 건너뛴다. 유효한 추적 pose가 있으면 패널을 겨누지 않아도 짧은 레이를 표시한다. 추적 pose 자체를 OS가 제공하지 않는 경우에는 JS로 만들어내지 않는다.
- 풋페달은 기존 1회 타격/120ms 표시/실제 keyup 후 재무장 방식을 유지한다. 몰입 XR이 여전히 visible인 상태에서 DOM blur가 발생해도 물리 누름 latch를 풀지 않는다. 따라서 꾹 누른 상태의 반복/중복 이벤트로 재타격되거나 컨트롤러 표시가 바뀌지 않는다.

추가 검증: 실제 MP3에서 ±10초, 정지 위치 복귀, 플레이어 하단 잡기/이동/확대/거리/놓기/저장/복원, 이동 후 버튼, 통합 패널 크기/저장, 잡지 않은 상태 조절 차단, 최소·최대 제한, 8개 실제로 보이는 테두리, 킥 타격 시 컬러/파동/복귀. 추가 키보드 XR 소스와 DOM blur 및 100개 반복 입력 동안 킥 1회/양손 타격 16회/두 컨트롤러 레이 지속을 확인했다. 기존 전체 985개 노트, 풋페달/Grip, 패널 이동/저장, VR/AR 회귀 테스트도 통과했다. 모두 Windows 모의 XR 결과이며 실제 Quest의 USB 입력·프레임 안정성은 별도 실기 확인이 필요하다.
