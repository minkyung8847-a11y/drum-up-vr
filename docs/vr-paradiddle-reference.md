# Paradiddle를 참고한 자유 연주 개선

조사일: 2026-10-20. 공식 설명과 개발자 공개 연주 영상을 먼저 확인한 뒤,
현재 Three.js / WebXR 구조에서 상호작용과 렌더링 경로를 개선했다.
Paradiddle의 자산이나 소스 코드는 가져오지 않았다.

## 참고 자료와 적용 범위

- [공식 사이트](https://paradiddleapp.com/): 자유로운 악기 배치와 반응성 중심의 VR 연주.
- [공식 FAQ](https://paradiddleapp.com/faq/): 타격 속도·위치 및 라운드 로빈에 따른 음색 변화.
- [공식 프레스 키트](https://paradiddleapp.com/press-kit/): 악기·컨트롤 보정 및 오디오 지연 개선 방향.
- [Steam 공식 소개](https://store.steampowered.com/app/685240/Paradiddle/): 위치·강도에 반응하는 소리와 네이티브 오디오 출력 방식.
- [개발자 공개 Whiplash 연주 영상](https://www.youtube.com/watch?v=cZKheiV1n4c):
  앉은 연주자의 양손 스트로크, 가까운 악기 배치, 1인칭 화면을 관찰했다.
  영상만으로 입력 지연이나 실제 연주 감각을 측정했다고 판단하지 않았다.

현재 드럼 배치는 이미 스네어 앞, 하이햇 왼쪽, 플로어 탐 오른쪽, 랙 탐 앞쪽,
심벌 바깥쪽의 구조이며 가림 검사도 통과한다. 이번 변경에서는 드럼 위치,
각도, 지름, 깊이, 모델·재질·색상, 카메라·좌석, 배경·조명·UI를 유지했다.
낙하 노트는 계속 비활성화되어 있다.

## 구현한 변경

- 컨트롤러 입력 슬롯을 4개 확보했다. 손 추적·시선 등의 입력이 먼저 연결돼도
  왼손/오른손 컨트롤러를 실제 handedness로 구분한다. 스틱은 여전히 2개다.
- 비활성화 후 재활성화 시 연결 정보를 보존한다. 추적 상실·가상 위치·가려진
  세션에서는 스틱과 판정을 숨기고, 정상 추적 복구 시 첫 프레임의 이전/현재
  위치를 일치시켜 순간 이동이 타격으로 해석되지 않도록 한다.
- 양손 기본 스틱 각도를 그립 기준 위쪽 12도로 설정했다. 기존 보정 패널에서
  각 손을 별도로 조절할 수 있고, 데스크톱 미리보기도 같은 기본 보정을 사용한다.
  실제 위치·회전은 XR 그립을 직접 따르며 추가 보간 지연을 넣지 않는다.
- 빠른 대각선 움직임이 한 프레임 사이에 보조 영역에 들어갔다 나오는 경우도
  검사한다. 심벌 곡면 교차점을 보정하고, 한 스윙으로 여러 표면을 통과하면
  먼저 접촉한 유효 표면 하나를 선택한다. 기존 넓은 보조 판정도 유지한다.
- 타격 강도는 전체 이동 속도 대신 표면을 향한 접근 속도로 계산한다.
  작은 고스트 노트와 강한 타격의 볼륨 차이를 확대했다. 기존 샘플과 겹침 재생,
  드럼헤드 진동·심벌 흔들림/빛·양손 햅틱은 유지한다.
- 소리 준비 요청에 세대 번호를 부여했다. 이전 악기 세트의 로딩 완료/실패가
  현재 세트의 준비 상태를 덮어써서 지연된 타격을 허용하는 문제를 막는다.
- 동일한 고정 러그 부품 792개를 7개 인스턴스 묶음으로 렌더링한다.
  기존 기하 도형과 재질, 위치를 그대로 사용하며 헤드·심벌 등 움직이는 부품은
  독립적으로 유지한다. 원본 메시를 보존하므로 정리 시 원상 복구된다.

기존 판정 설정은 유지한다: 최소 속도 0.07 m/s, 접근 속도 0.035 m/s,
누적 스트로크 4 mm, 반각 65도, 표면 위 32 cm / 아래 8 cm, 반경 여유 12 cm,
회복 이동 8 mm, 손별 쿨다운 40 ms. 도달 거리 제한도 그대로다.
볼륨 응답은 접근 속도 v에 대해 `0.12 + 0.88 × (1 − exp(−v / 1.4))`이다.
음색 레이어나 임의의 가짜 타격을 추가하지 않았다.

## 검증 결과

- 전체 8개 악기 보조 판정 1,088개 조합: 잘못된 악기 선택/복수 타격 없음.
- 60/72/90/120 Hz 양손 가벼운 타격, 빠른 교차·대각선 스윙, 24회 교대 롤,
  강약 분리, 정지·추적 상실·프레임 지연의 오발 방지 검사 통과.
- 컨트롤러 순서 반전, 늦은 왼손 연결, 앞 슬롯의 비컨트롤러 입력, 재활성화,
  복구 첫 프레임, 양손 햅틱 및 미지원 장치 대체 경로 검사 통과.
- 기존 마우스 입력, 모든 악기의 실제 샘플 매핑, 20개 중첩 오디오 음성,
  헤드/심벌 피드백, 오디오 로딩 경쟁 상태 검사 통과.
- 드럼 치수·기하 도형·재질 보존, 본체 간섭 없음, 앉은 시점의 주요 표면
  가림 없음, 카메라 동작 및 노트 비활성화 검사 통과.
- 동일한 전체 장면의 드로 호출: 1,104 → 319회(약 71% 감소).
  독립적인 전체 키트 검사에서는 960 → 175회이며 삼각형 603,600개가 동일하다.
  인스턴스 위치 오차는 0.000000053 m 미만, 비교 이미지의 유의한 픽셀 차이는
  576,000개 중 1개였다. 이는 데스크톱 렌더링 검사이며 VR FPS 수치는 아니다.
- 프로덕션 빌드 및 변경 파일 lint 통과. 전체 저장소 lint는 기존
  `scripts/finish-brand-theme.mjs:12` 구문 오류 때문에 통과하지 못하는 상태다.

주요 검사: `check-vr-assisted-strikes.mjs`, `check-vr-physical-strikes.mjs`,
`check-xr-drumsticks.mjs`, `check-vr-layout.mjs`, `check-vr-hits.mjs`,
`check-vr-audio-readiness.mjs`, `check-vr-hardware-instances.mjs`,
`check-vr-free-play.mjs`, `check-first-person-camera.mjs`.

## Paradiddle과 남아 있는 차이

현재는 기존 샘플의 볼륨 다이내믹을 사용한다. Paradiddle의 다층 샘플,
타격 위치별 음색, 라운드 로빈 수준의 음색 다양성은 구현하지 않았다.
DRUM UP은 브라우저 Web Audio를 사용하므로 네이티브 WASAPI/ASIO 출력과
동일한 지연을 보장할 수 없다. 녹음·교육·추가 악기 등은 이번 작업 범위가 아니다.

실제 VR 헤드셋은 사용하지 않았다. 기기별 그립 각도·왼손 연결 복구,
물리적 도달 거리와 장시간 편안함, 실제 햅틱 감각, 귀로 느끼는 오디오 지연,
고속 연주의 정확도 및 지속적인 헤드셋 FPS는 하드웨어 검증이 필요하다.
